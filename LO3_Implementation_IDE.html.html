Introduction

Le critère LO3 du BTEC te demande de démontrer que tu sais utiliser un IDE (Integrated Development Environment) pour transformer un algorithme en application exécutable. Cela couvre quatre compétences :

  1. Développer des applications simples qui implémentent des algorithmes de base.
  2. Écrire du code logique et maintenable.
  3. Prendre en compte les considérations de sécurité et proposer des solutions.
  4. Compiler, gérer et déployer le code dans l'environnement cible.
IDE recommandé : IntelliJ IDEA (Community Edition) ou Eclipse. Les deux sont gratuits, puissants et largement utilisés en entreprise. Ce cours utilise IntelliJ IDEA comme référence.

L'IDE : environnement de développement

Un IDE est un logiciel qui regroupe tous les outils nécessaires au développement :

OutilRôleExemple dans IntelliJ
Éditeur de codeÉcrire le code avec coloration syntaxique et auto-complétion.Éditeur principal avec code completion.
CompilateurTraduire le code source Java en bytecode.javac intégré, compilation à la volée.
DébogueurExécuter le code pas à pas pour trouver les bugs.Breakpoints, watch list, pas-à-pas.

Pourquoi un IDE plutôt qu'un simple éditeur de texte ? Un IDE te fait gagner du temps (auto-complétion, refactoring), t'aide à éviter les erreurs (soulignement rouge, suggestions) et facilite le débogage (exécution pas à pas). C'est l'outil standard en entreprise.

Le cycle de vie du code dans un IDE

Voici les étapes que tu vas suivre pour chaque projet :

2. Compiler → bytecode (.class)

Dans IntelliJ IDEA, ces étapes sont largement automatisées : tu cliques sur ▶️ pour exécuter, et l'IDE compile et exécute pour toi.

Développer une application simple

Voici un exemple complet d'application Java qui implémente un algorithme de base (calcul de moyenne) :

public class CalculMoyenne {
    public static void main(String[] args) {
        int[] notes = {12, 15, 8, 17, 10};
        int somme = 0;

        for (int note : notes) {
            somme += note;
        }

        double moyenne = (double) somme / notes.length;
        System.out.println("Moyenne : " + moyenne);
    }
}
Exemple concret de projet : dans le cadre de ClubConnect, tu pourrais développer une classe Membre avec une méthode calculerCotisation(), puis une classe GestionClub qui utilise une liste de membres et calcule le total des cotisations. C'est exactement le type d'application simple attendu par le LO3.

Code logique et maintenable

Un code logique est un code qui se lit de haut en bas et dont chaque méthode fait une seule chose. Un code maintenable est un code que quelqu'un d'autre (ou toi dans 6 mois) peut comprendre et modifier sans tout casser.

Les 5 règles d'or

RègleMauvaise pratiqueBonne pratique
Nommer clairement int x = 5; int nombreDeMembres = 5;
Une méthode = une action void traiter() { ... 50 lignes ... } void valider() + void enregistrer() + void afficher()
Éviter la duplication (DRY) Copier-coller le même calcul 3 fois. Extraire dans une fonction réutilisable.
Indenter et commenter Tout sur une ligne, sans commentaire. Code indenté, commentaires sur le "pourquoi", pas le "comment".
Gérer les cas d'erreur Ignorer les erreurs potentielles. Vérifier les paramètres, utiliser try/catch.

Exemple — refactorisation

Avant (code peu maintenable) :

public void traiter() {
    // 50 lignes de code qui font tout
}

Après (code maintenable) :

public void traiter() {
    if (!valider()) return;
    enregistrer();
    afficher();
}

private boolean valider() { ... }
private void enregistrer() { ... }
private void afficher() { ... }

Considérations de sécurité

La sécurité est un critère essentiel du LO3. Un code qui fonctionne mais qui est vulnérable n'est pas un bon code. Voici les 4 menaces principales à connaître :

MenaceDescriptionSolution
Injection SQL Un utilisateur saisit du code SQL dans un champ, qui est exécuté par la base de données. Requêtes préparées (PreparedStatement) avec paramètres liés. Ne jamais concaténer les entrées utilisateur dans une requête.
Injection de commandes Un utilisateur saisit une commande système qui est exécutée par le programme. Valider les entrées avec une liste blanche (allow-list) de caractères autorisés.
XSS (Cross-Site Scripting) Un utilisateur injecte du code JavaScript dans une page web. Échapper les caractères spéciaux (<, >, &) avant affichage.
Débordement de tampon Un utilisateur saisit plus de caractères que prévu, ce qui écrase la mémoire. Utiliser des types de données adaptés (ex. String plutôt qu'un tableau de taille fixe) et valider la longueur.

Exemple concret — Validation des entrées

Mauvaise pratique (vulnérable) :

// Ne JAMAIS faire ça
String nom = champNom.getText();
if (nom != null && nom.length() > 0) {
    // Accepte n'importe quoi, y compris des caractères malveillants
}

Bonne pratique (sécurisée) :

private boolean validerNom(String nom) {
    if (nom == null || nom.trim().isEmpty()) {
        return false; // Rejeter les noms vides
    }
    if (nom.length() > 50) {
        return false; // Rejeter les noms trop longs
    }
    // Liste blanche : uniquement lettres, espaces et tirets
    return nom.matches("[a-zA-ZÀ-ÿ\\s-]+");
}
Règle d'or : toute entrée utilisateur doit être considérée comme potentiellement malveillante. On ne fait jamais confiance à ce qui vient de l'extérieur (formulaire, fichier, réseau).

Build et déploiement

Une fois le code écrit et testé, il faut le compiler, le packager et le déployer pour qu'il puisse être utilisé.

Les outils de build : Maven et Gradle

OutilRôleCommande
MavenGère les dépendances et le cycle de build via un fichier pom.xml.mvn clean package
GradleMême rôle, mais plus rapide et plus flexible../gradlew build

Ces commandes produisent un fichier JAR (Java ARchive) qui contient le bytecode et les dépendances, prêt à être exécuté.

Le cycle de déploiement

  1. Développer le code dans l'IDE.
  2. Compiler avec mvn clean package ou gradle build.
  3. Tester localement l'exécutable (ex. java -jar monApp.jar).
  4. Déployer sur le serveur ou la plateforme cible (serveur d'application, conteneur Docker, cloud...).
Pour ClubConnect : dans un premier temps, l'application sera une application console Java. Le déploiement consistera simplement à produire un JAR exécutable et à le lancer avec la commande java -jar ClubConnect.jar.

Synthèse et checklist

Checklist LO3 — avant de rendre un projet

  • ✅ Mon application compile sans erreur dans l'IDE.
  • ✅ Mon application s'exécute et produit les résultats attendus.
  • ✅ Mon code est indenté et les noms de variables/méthodes sont clairs.
  • ✅ Chaque méthode fait une seule chose.
  • ✅ J'ai validé les entrées utilisateur (taille, type, caractères autorisés).
  • ✅ J'ai géré les cas d'erreur (try/catch, valeurs par défaut).
  • ✅ J'ai testé mon application avec des données normales et des données invalides.
  • ✅ J'ai produit un JAR exécutable et je sais le lancer.
