1 · Qu'est-ce qu'un algorithme ?

Un algorithme est une suite finie et ordonnée d'opérations permettant de résoudre un problème. C'est une recette : on décrit pas à pas ce qu'il faut faire pour transformer des données d'entrée en résultat.

Définition formelle : un algorithme est une méthode de calcul qui prend zéro ou plusieurs entrées, produit au moins une sortie, et qui garantit de se terminer en un nombre fini d'étapes.

Exemple concret : faire du café

Avant même de parler d'informatique, on manipule des algorithmes tous les jours :

Algorithme FaireUnCafé
    Entrée : eau, café moulu, tasse
    Sortie : tasse de café chaud

    1. Remplir le réservoir d'eau
    2. Mettre le filtre dans le porte-filtre
    3. Ajouter 2 cuillères de café moulu
    4. Placer la tasse sous la buse
    5. Lancer la machine
    6. Attendre la fin de l'écoulement
    7. Retirer la tasse

Ce texte est un algorithme : il a des entrées (eau, café), une sortie (tasse de café), une suite d'opérations ordonnées, et il se termine.

Différence entre algorithme et programme

AlgorithmeProgramme
NatureDescription abstraite de la solutionImplémentation concrète dans un langage
LangagePseudo-code, langage naturel, organigrammeJava, Python, C#, etc.
DépendanceIndépendant de la machineDépend d'un compilateur / interpréteur
VérificationVérifié par la logiqueVérifié par exécution et tests
Règle d'or : on conçoit toujours l'algorithme avant d'écrire le programme. Coder sans algorithme, c'est construire une maison sans plan.

2 · Les 5 propriétés d'un algorithme

PropriétéSignificationContre-exemple
1. Finitude L'algorithme doit se terminer après un nombre fini d'étapes. while(true) { } — ne se termine jamais.
2. Définition précise Chaque étape est définie sans ambiguïté. « Ajouter un peu de sel » — combien ?
3. Entrées Zéro ou plusieurs données en entrée. —
4. Sorties Au moins un résultat produit. Un algorithme qui calcule sans jamais rien retourner.
5. Efficacité Chaque opération est réalisable (par un humain ou une machine). « Trouver la pensée de l'utilisateur » — impossible.

3 · Le pseudo-code

Le pseudo-code est un langage intermédiaire entre le français et le code réel. Il utilise une syntaxe proche du Java (comme dans ton cours P1-P4) mais reste lisible par un humain.

Structure de base

Algorithme NomDeLAlgorithme
    // Déclaration des variables
    Variables variable1 : type1
             variable2 : type2

    Début
        // Instructions
        instruction1
        instruction2
        ...
        Retourner resultat
    Fin

Instructions courantes en pseudo-code

Pseudo-codeSignification
x ← 5 ou x = 5Affecter la valeur 5 à la variable x
saisir(x)Lire une valeur au clavier et la mettre dans x
afficher(x)Afficher le contenu de x
si (condition) alors … sinon … finsiAlternative
tant que (condition) faire … fintantqueBoucle tant que
pour i de 1 à n faire … finpourBoucle pour

Exemple — somme de deux nombres

Algorithme Somme
    Variables a, b, resultat : entier

    Début
        saisir(a)
        saisir(b)
        resultat ← a + b
        afficher(resultat)
    Fin

4 · Les organigrammes

Un organigramme (ou flowchart) est une représentation graphique d'un algorithme. Chaque type d'action a une forme de symbole précise.

Les symboles standards

SymboleNomUtilisation
DébutOvale / TerminaisonDébut et fin de l'algorithme

x > 0 ?LosangeDécision (condition if/else)
saisir(x)ParallélogrammeEntrée / sortie (lire, afficher)
↓FlècheSens du flux d'exécution

Exemple — maximum de deux nombres

Début

saisir(a, b)
↓
a > b ?
↙ OUI           NON ↘
max ← a      max ← b

Avantage de l'organigramme : il montre visuellement les branches. C'est très utile pour repérer les boucles et les conditions imbriquées. Inconvénient : devient illisible dès qu'un algorithme dépasse 20-30 étapes.

6 · Complexité de base

La complexité mesure le coût d'un algorithme : combien de temps il prend (complexité temporelle) et combien de mémoire il utilise (complexité spatiale). On l'exprime en fonction de la taille des données, notée n.

Notation grand O — les 5 classes à connaître

NotationNomSignificationExemple
O(1)ConstantTemps identique quelle que soit la tailleAccès à tableau[5]
O(log n)LogarithmiqueTrès rapide, divise par 2 à chaque étapeRecherche dichotomique
O(n)LinéaireProportionnel à la tailleParcours de tableau
O(n log n)Quasi-linéaireBon compromis pour les trisTri fusion, tri rapide
O(n²)QuadratiqueDouble boucle imbriquéeTri à bulles, tri par sélection

Comparaison visuelle pour n = 1000

ComplexitéOpérations approximativesTemps (à 1 million d'op/s)
O(1)11 microseconde
O(log n)1010 microsecondes
O(n)1 0001 milliseconde
O(n log n)10 00010 millisecondes
O(n²)1 000 0001 seconde
À retenir : quand n double, O(n²) est 4 fois plus lent, tandis que O(n) est seulement 2 fois plus lent. C'est pour ça qu'on évite les algorithmes quadratiques sur de grandes données.

Comment compter la complexité ?

Méthode simple : on compte les boucles imbriquées.

Structure du codeComplexité
Aucune boucleO(1)
1 boucle simple for (i=0; i<n; i++)O(n)
2 boucles imbriquéesO(n²)
3 boucles imbriquéesO(n³)
Boucle qui divise n par 2 à chaque tourO(log n)

TD — Le tri à bulles (Bubble Sort)

Le tri à bulles est l'algorithme de tri le plus simple à comprendre. Son idée : comparer les éléments deux à deux, échanger s'ils sont mal ordonnés, et laisser les plus grands « remonter » comme des bulles vers la fin du tableau.

Idée clé : à chaque passage (une « passe »), le plus grand élément restant se retrouve à sa place définitive à la fin. Après n-1 passes, tout le tableau est trié.

Règle : pour un tableau de n éléments, il faut au plus n-1 passes. À chaque passe, on peut ignorer le dernier élément (déjà trié). C'est pour ça que la boucle interne fait n - 1 - i comparaisons.

Pseudo-code

Version simple

Algorithme TriBulles
    Variables tab : tableau[1..n] d'entiers
             i, j, temp : entier

    Début
        Pour i de 1 à n-1 faire
            Pour j de 1 à n-1-i faire
                Si tab[j] > tab[j+1] alors
                    temp ← tab[j]
                    tab[j] ← tab[j+1]
                    tab[j+1] ← temp
                FinSi
            FinPour
        FinPour
        Retourner tab
    Fin

Code Java

Version simple

public static void triBulles(int[] tab) {
    int n = tab.length;
    int temp;

    for (int i = 0; i < n - 1; i++) {
        for (int j = 0; j < n - 1 - i; j++) {
            if (tab[j] > tab[j + 1]) {
                // échange
                temp = tab[j];
                tab[j] = tab[j + 1];
                tab[j + 1] = temp;
            }
        }
    }
}

Complexité du tri à bulles

CasComparaisonsÉchangesComplexité
Meilleur cas (tableau déjà trié)n-10O(n)
Cas moyen~n²/2~n²/4O(n²)
Pire cas (tableau inversé)n(n-1)/2n(n-1)/2O(n²)
Conclusion : le tri à bulles est O(n²) dans le cas moyen et le pire cas. C'est un algorithme lent sur de grands tableaux, mais il est très simple à comprendre — c'est pour ça qu'on l'enseigne en premier.

Optimisations du tri à bulles

Optimisation 1 — Détecter si le tableau est déjà trié

Si une passe entière s'est faite sans aucun échange, c'est que le tableau est trié : on peut arrêter immédiatement.

public static void triBullesOptim(int[] tab) {
    int n = tab.length;
    boolean echange;

    for (int i = 0; i < n - 1; i++) {
        echange = false;
        for (int j = 0; j < n - 1 - i; j++) {
            if (tab[j] > tab[j + 1]) {
                int temp = tab[j];
                tab[j] = tab[j + 1];
                tab[j + 1] = temp;
                echange = true;
            }
        }
        if (!echange) {
            break;   // tableau déjà trié → on sort
        }
    }
}

Optimisation 2 — Réduire la zone de tri

Après chaque passe, la fin du tableau est triée. On peut mémoriser la position du dernier échange pour réduire la zone à parcourir à la passe suivante.

Optimisée (drapeau)O(n)O(n²)O(n²)

Exercice 5 — Comparer deux algorithmes de tri

Le tri à bulles est O(n²). Le tri par insertion est aussi O(n²) dans le pire cas, mais très rapide sur des tableaux presque triés. Le tri rapide (Quicksort) est O(n log n) en moyenne.
