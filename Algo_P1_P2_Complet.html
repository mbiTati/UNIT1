Partie 1 — Variable, type, séquence

Introduction

À l'origine l'algorithmique a été pensée pour introduire les concepts liés à la programmation ; pour ce faire on pensait qu'il fallait se dégager des contraintes syntaxiques des langages pour se concentrer justement sur les concepts. Cette approche est aujourd'hui abandonnée (ou presque) et au contraire nous allons utiliser une syntaxe très proche des langages "modernes".

À cela plusieurs raisons : à l'époque les langages étaient très différents, il n'y avait quasiment rien de commun par exemple entre le C et le COBOL ; ce n'est (presque) plus le cas aujourd'hui où l'on assiste à une convergence des syntaxes, par exemple le C# et Java sont vraiment très proches, à telle enseigne que sur des séquences simples on peut pratiquement faire du copier/coller d'un langage à l'autre et à un iota près cela fonctionne ! Même le PHP dans sa dernière version tend à rejoindre ces derniers.

Un autre reproche que l'on pouvait faire à l'algorithmique, c'est qu'il fallait quand même mettre en place un formalisme, formalisme qui n'était ni normalisé ni standardisé et qui au final était abandonné dès lors qu'on passait aux langages réels.

En conclusion, nous allons faire de l'algorithmique, mais dans une syntaxe très proche du Java qui est devenu au fil des années un standard ; on aurait tout aussi bien pu choisir le C# voire le PHP 7 !

Premier algorithme

Nous allons étudier notre premier algorithme et à travers lui quelques éléments communs à tous les algorithmes.

Cet algorithme déclare trois variables, affecte la valeur 10 à la première variable, la valeur 2 à la deuxième, puis effectue la somme des deux variables à une troisième variable dont le contenu est affiché.

program Premier
{
    int nombre1, nombre2, resultat;
    nombre1 = 10;
    nombre2 = 2;
    resultat = nombre1 + nombre2;
    afficher(resultat);
}

  • Du texte : "Le résultat est :"

  • Le résultat d'un calcul entre deux variables ou une constante et une variable

La notion de variable

Les langages de programmation font un usage intensif de variables, cela permet de réutiliser plusieurs fois un même programme sans avoir à le réécrire à chaque fois. Il faut considérer une variable comme une boîte : cette boîte dispose d'un nom qui permettra de la distinguer des autres boîtes, et d'un contenu qui pourra varier.

Exemple de boîte : nom de la variable TOTAL_TTC, contenu 125,75.

Pour exister une variable doit d'abord être déclarée et avoir un type, cela se fait toujours en début de programme, avant la première instruction, exemple :

double total_ht, total_ttc;
int quantite;

Les variables total_ht et total_ttc sont déclarées de type double (nombres décimaux), c'est à dire qu'elles pourront recevoir des valeurs décimales (20.6, 125.75, …).

Important : en informatique, la marque décimale est le point . et non la virgule.

La variable quantite est déclarée de type int (entier), elle ne pourra donc contenir que des nombres entiers (1, 12, 789, …), mais pas des nombres décimaux.

Sur les variables on peut effectuer les opérations suivantes :

Affecter une valeur à une variable :

total_ttc = 125.75;

Affecter le résultat d'une opération à une variable :

total_ttc = 125.75 * 1.206;
total_ttc = total_ht * taux_tva;

Affecter le contenu d'une variable à une autre variable :

prix1 = prix2;

Afficher le contenu d'une variable :

afficher(total_ttc);

La notion de type

Pour faire comprendre la notion de variable nous avons pris l'image d'une boîte ayant un nom. À cela il faut ajouter le type qui indique quelle sorte de contenu peut être mis dans cette boîte. Continuons à filer la métaphore : si on dispose de trois boîtes, sur l'une est marqué Chocolat, sur l'autre est marqué Sel, et enfin sur la dernière est marqué Sucre — il ne viendrait à l'idée de personne de mettre du sucre dans la boîte à sel ! En effet la boîte à Sel ne pourra contenir que du Sel et rien d'autre, Sel est le type de cette boîte.

Pour les variables c'est pareil : la variable quantite est de type int, cela signifie que l'on peut écrire :

quantite = 10;
quantite = 2 * nombre1;

mais l'on ne peut pas écrire :

quantite = 10.3;

En effet 10.3 est une valeur de type décimal alors que la variable quantite est de type int (entier).

Pour le moment nous nous limiterons à deux types :

  • int qui ne peut contenir que des nombres entiers : 0, 1, 2 … 125, 145879 …
  • double qui ne peut contenir que des nombres décimaux : 0.5, 18.75, 852.127 …

En réalité, mais on le verra plus tard, le type double englobe le type int, en effet il sera tout à fait autorisé d'écrire les instructions suivantes :

double nombre1;
nombre1 = 5;

Le langage Java (langage sur lequel on s'appuie) se chargera de transformer 5 en 5.0. Mais en ce qui nous concerne on s'abstiendra de pratiquer ce genre d'écriture pour le moment : si on veut manipuler des entiers, on déclarera une variable de type int, et si l'on veut manipuler des nombres décimaux on déclarera une variable de type double.

Quelques remarques

  • Vous aurez remarqué que toutes les lignes se terminent par un point-virgule (;). C'est un marqueur indiquant que la ligne d'instruction s'arrête ici.
  • On ne met pas d'accent ou de signe diacritique aux variables.
  • Les noms des types (int, double, String …) sont en anglais.
  • Les variables et instructions sont en minuscules.

La séquence

C'est la structure de traitement la plus simple, celle où les instructions s'exécutent les unes après les autres dans l'ordre où elles ont été écrites. Ainsi le groupe d'actions suivantes constitue une séquence.

nombre1 = 10;
nombre2 = 2;
resultat = nombre1 + nombre2;
afficher(resultat);

Partie 2 — Structure de contrôle if, opérateurs de comparaison

Objectifs

  • Type de donnée : char.
  • Primitives saisir() et afficher().
  • Opérateurs de comparaison.
  • Structure de contrôle : l'alternative if { ... }, if {...} else { ... }

Problème

Que fait cet algorithme ?

program Compare {
    int nombre1, nombre2;
    saisir(nombre1);
    saisir(nombre2);
    if (nombre1 <= nombre2) {
        afficher(nombre1, "est <= " + nombre2);
    }
}

La convention de blocs Java

Puisque nous nous appuyons sur le langage Java, nous allons prendre l'habitude d'en utiliser tout de suite les us et coutumes, et notamment l'écriture des blocs d'instructions qui s'écrivent toujours comme suit :

structure_controle {
    actions;
}

L'ouverture du bloc d'instructions portées se fait juste à la suite de la structure de contrôle qui porte ce bloc, exemples :

program Compare {
    actions;
}

if (nombre1 <= nombre2) {
    actions;
}
Description du programme : saisie de deux nombres ; si le premier nombre est inférieur ou égal au deuxième, affichage que le premier nombre est plus petit ou égal au deuxième.

La primitive saisir()

saisir(variable) : primitive de traitement permettant d'effectuer une saisie (sous-entendu au clavier) et d'affecter ce qui a été tapé à une variable, exemple :

saisir(taux_tva);

Après réalisation de cette instruction, la variable taux_tva contiendra ce qui a été saisi par l'utilisateur au clavier, par exemple 5.2 ou bien 20.6.

La structure if

if (condition) {
    action1;
    action2;
    actionN;
}

Si la condition entre parenthèses est vérifiée alors les actions définies entre les délimiteurs de bloc { et } seront exécutées, sinon elles ne le seront pas. if(condition) est une structure de contrôle de type alternative.

Les délimiteurs de blocs fixent les limites des actions conditionnées par le if. Dans l'exemple ci-dessous, l'instruction afficher("Fin du programme"); s'exécutera que la condition soit vérifiée ou non, car elle ne fait pas partie du bloc soumis à la condition :

if (nombre1 <= nombre2) {
    afficher(nombre1, "est <= " + nombre2);
}
afficher("Fin du programme");

Les opérateurs de comparaison

expression1 <= expression2 : la suite <= est un opérateur de comparaison qui veut dire : est-ce que expression1 est plus petite ou égale à expression2 ? Si la réponse est positive on dira que la condition est vérifiée (ou vraie). Si la réponse est négative on dira que la condition est non vérifiée (ou fausse). Expression peut être une variable (nombre1, a, x, ...) ou une constante (0, 234, ...).

Il y a d'autres opérateurs de comparaison : <, >, >=, ==, !=

Égalité, différence, négation

L'opérateur d'égalité : comme l'opérateur d'affectation est le signe =, il a fallu trouver une autre façon de tester l'égalité entre deux valeurs, c'est l'opérateur == qui a été choisi. Donc si on veut savoir si deux variables contiennent des valeurs égales, il faudra écrire :

if (nombre1 == nombre2)

L'opérateur de différence : l'opérateur de différence (ou de non égalité) est !=, donc si l'on veut savoir si deux variables (ou une variable et une constante) sont différentes, on écrira :

if (nombre1 != nombre2)
if (nombre1 != 3)

L'opérateur de négation : l'opérateur de négation est !. Il est utilisé, on l'a vu, pour construire la différence (non égalité) ; on le retrouvera souvent lorsqu'on abordera le type booléen.

Problème

Si le premier nombre saisi n'est pas inférieur ou égal au deuxième, on n'a aucun message nous l'indiquant. Il faut donc modifier le programme comme suit :

program Compare {
    int nombre1, nombre2;
    saisir(nombre1);
    saisir(nombre2);
    if (nombre1 <= nombre2) {
        afficher(nombre1, "est <= " + nombre2);
    } else {
        afficher(nombre1, "est >" + nombre2);
    }
}

Nous venons d'introduire la structure de contrôle Si … Sinon (if … else).

if … else

if (condition) {
    actions1;
} else {
    actions2;
}

Si la condition est vérifiée, alors les actions 1 seront exécutées et on sort du if ; si la condition n'est pas vérifiée (else), ce seront alors les actions 2 qui seront exécutées puis on sortira du if.

Problème

Le programme COMPARE est incomplet, en effet si nombre1 == nombre2, on ne le sait pas.

program CompareV2 {
    int nb1, nb2;
    saisir(nb1);
    saisir(nb2);
    if (nb1 < nb2) {
        afficher(nb1, " est < à " + nb2);
    } else {
        if (nb1 > nb2) {
            afficher(nb1, " est > à " + nb2);
        } else {
            afficher("Ils sont égaux");
        }
    }
}

On peut fort bien imbriquer des if ... else puisque cette structure est elle aussi une action. Cela permet de tester les trois conditions >, < et ==. À noter que l'égalité n'a pas été testée, elle a été déduite de la non supériorité et de la non infériorité.

Les opérateurs ET, OU

Il est possible de combiner des conditions en utilisant les opérateurs ET (&&) ou OU (||). On peut légitimement être surpris par les symboles utilisés pour représenter le ET et le OU — on s'attendrait plutôt à voir AND et OR — mais ce n'est pas le cas ; encore une fois nous avons fait le choix de "coller" plus ou moins fidèlement au langage Java, pour qu'une fois la phase algorithmique passée, on passe très facilement à la codification en Java ou même si besoin en C# !

if ((condition1) && (condition2)) {
    actions;
}
if ((condition1) || (condition2)) {
    actions;
}

L'opérateur && (ET) : les actions portées par le Si ne seront exécutées que si la condition1 est vérifiée ET que la condition2 est vérifiée. Exemples :

nb1 = 2;
nb2 = 5;
nb3 = 8;
nb4 = 10;

if ((nb1 < nb2) && (nb3 < nb4)) {
    afficher("C'est vrai");
} else {
    afficher("C'est faux");
}

Dans ce cas l'expression "C'est vrai" sera affichée car les deux conditions sont vérifiées : nb1 est plus petit que nb2 ET nb3 est plus petit que nb4.

if ((nb1 < nb2) && (nb3 == nb4)) {
    afficher("C'est vrai");
} else {
    afficher("C'est faux");
}

Dans ce cas l'expression "C'est faux" sera affichée, car la condition 1 est bien vérifiée mais la condition 2 ne l'est pas : en effet nb3 n'est pas égal à nb4.

L'opérateur OU (||) :

if ((nb1 < nb2) || (nb3 == nb4)) {
    afficher("C'est vrai");
} else {
    afficher("C'est faux");
}

Dans ce cas l'expression "C'est vrai" sera affichée car il suffit que l'une des deux conditions soit vérifiée, ce qui est le cas : si nb3 n'est pas égal à nb4, en revanche nb1 est bien plus petit que nb2.

Le type char

Ce type de donnée est codé sur 1 octet qui peut prendre une valeur allant de 0 à 255. Tous les caractères (lettres, chiffres, ponctuation, et d'autres signes) sont codés dans une table appelée table ASCII. Les caractères sont notés entre apostrophes ('A', 'B', 'C', '0', '1', ...).

L'affectation d'une valeur de type caractère à une variable est identique aux autres types de données :

char lettre;
lettre = 'F';

Remarque : le caractère 'A' est codé 65d, le caractère 'B' est codé 66d, donc l'expression 'A' < 'B' est tout à fait juste. Attention, il ne faut pas confondre le caractère '0' qui est une donnée de type char et le chiffre 0 qui est une donnée de type entier. Donc l'expression '0' == 0 est impropre car on compare deux données de types différents.

Une erreur commune est de croire que seuls les nombres peuvent être comparés ; en fait deux données de même type peuvent parfaitement être comparées, et ce en utilisant n'importe quel opérateur. Les lignes suivantes sont parfaitement correctes :

int nb1, nb2;
saisir(nb1, nb2);
if (nb1 < nb2) {
    actions
}

char car1, car2;
saisir(car1, car2);
if (car1 >= car2) {
    actions;
}

Il est bien évident que "in fine" la comparaison de deux caractères se fait par celle de leur code ASCII, qui eux-mêmes ne sont qu'une représentation du code binaire. Mais puisque les langages savent faire la comparaison de deux caractères, il ne faut pas s'en priver !

Une variable définie dans un type de donnée ne peut être affectée, comparée, à un autre type de données.
