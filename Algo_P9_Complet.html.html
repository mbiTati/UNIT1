Le problème initial

Reprenons notre petit problème de coordonnées de points vu dans la première partie. À l'issue de ce programme on savait que les coordonnées des points 1, 2, 3 et 4 étaient correctes ou non, mais on avait perdu ces coordonnées, or on souhaite les conserver.

Si l'on reprend notre application, on pourrait définir autant de couples de variables (ordonnee, abscisse) qu'il y a de points et écrire ceci :

program PointsV2 {
    saisir(ordonnee1);
    saisir(abscisse1);
    point1 = verifie();
    saisir(ordonnee2);
    saisir(abscisse2);
    point2 = verifie();
    // ...
}

static boolean verifie() {
    boolean point;
    if ((ordonnee >= 0) && (abscisse <= 480) && (abscisse >= 0) && (abscisse <= 640)) {
        point = true;
    } else {
        point = false;
    }
    return point;
}
Problème : cela ne fonctionnerait pas car la fonction verifie() ne sait travailler que sur les variables ordonnee et abscisse. Il faudrait que la fonction puisse travailler sur ses propres variables tout en récupérant les valeurs de celles qui sont gérées par le programme appelant. Cela existe (oui !), c'est le passage de paramètres.

Le passage de paramètres

program Parametres {
    int ordonnee1, ordonnee2, ordonnee3;
    int abscisse1, abscisse2, abscisse3;
    boolean point1, point2, point3;

    saisir(ordonnee1);
    saisir(abscisse1);
    point1 = verifie(ordonnee1, abscisse1);

    saisir(ordonnee2);
    saisir(abscisse2);
    point2 = verifie(ordonnee2, abscisse2);

    saisir(ordonnee3);
    saisir(abscisse3);
    point3 = verifie(ordonnee3, abscisse3);
}

static boolean verifie(int ordonnee, int abscisse) {
    boolean point;
    if ((ordonnee >= 0) && (abscisse <= 480) && (abscisse >= 0) && (abscisse <= 640)) {
        point = true;
    } else {
        point = false;
    }
    return point;
}

La déclaration de la fonction incorpore des paramètres :

static boolean verifie(int ordonnee, int abscisse)

La zone des paramètres est délimitée par les parenthèses et les paramètres ne sont ni plus ni moins que des variables qui sont déclarées dans cette zone. On dit que ce sont les paramètres formels.

Lorsque le programme appelant appelle cette fonction, il le fait en lui passant le contenu des variables indiquées entre les parenthèses :

point1 = verifie(ordonnee1, abscisse1);

Paramètres formels vs paramètres réels

Au moment où la fonction est appelée, le programme place à la place des variables, les valeurs qui sont contenues dans ces variables. On dit que ce sont les paramètres réels.

Ainsi si ordonnee1 et abscisse1 contiennent respectivement 48 et 243, lors de l'appel c'est cette ligne qui est exécutée :

point1 = verifie(48, 243);

Quand la fonction est activée, les variables contenues dans sa zone de paramètres sont initialisées avec les valeurs reçues. Ainsi ce sont les valeurs qui circulent entre le programme appelant et la fonction, cela explique que l'on puisse appeler une fonction (ou une procédure) avec des variables différentes :

point1 = verifie(ordonnee2, abscisse2);
point1 = verifie(ordonnee3, abscisse3);
Une fonction ou une procédure peut être appelée aussi bien par le programme principal que par n'importe quel sous-programme et ce autant de fois que nécessaire. Un sous-programme peut même s'appeler lui-même, cela s'appelle la récursivité, cette fonctionnalité sera étudiée plus tard.

Exemples de passage de paramètres

Le passage de paramètres ne concerne pas seulement des entiers, il concerne tous les types de données. On peut passer des valeurs par l'intermédiaire de variables ou de constantes.

program Convertir() {
    double apport, somme;
    String monnaieSrc, monnaieDest;

    apport = 100;
    monnaieSrc = "Euros";
    monnaieDest = "Dollars";

    somme = conversion(apport, monnaieSrc);
    afficher(apport + " " + monnaieSrc + " font : " + somme + " " + monnaieDest);

    somme = conversion(100, "Dollars");
    afficher(100 + " Dollars font : " + somme + " Euros");
}

static double conversion(double montant, String devise) {
    double resultat;
    resultat = 0;

    if (devise.compareTo("Euros") == 0) {
        resultat = montant * 0.86;
    } else {
        resultat = montant * 1.17;
    }
    return resultat;
}
LigneCommentaire
double conversion(double montant, String devise)La fonction conversion admet deux paramètres : le premier de type double et le deuxième de type String.
somme = conversion(apport, monnaieSrc);L'appel de la fonction se fait avec deux variables (apport et monnaieSrc).
somme = conversion(100, "Dollars");L'appel de la fonction se fait avec deux constantes (100 et "Dollars").

L'exécution du programme Convertir donne l'affichage suivant :

100.0 Euros font : 86.0 Dollars
100.0 Dollars font : 117.0 Euros

Procédures avec paramètres

Le passage de paramètres ne concerne pas seulement les fonctions, mais aussi les procédures.

Pour le moment les procédures ne seront utilisées que pour l'affichage, exemple :

static void affichage(double montant, double conv, String deviseSrc, String deviseDest) {
    afficher(montant + " " + deviseSrc + " font : " + conv + " " + deviseDest);
}

Dans le programme principal, son appel se ferait comme suit :

affichage(apport, somme, monnaieSrc, monnaieDest);
Nous verrons plus tard, lorsque nous étudierons la POO, que les procédures peuvent avoir d'autres utilités.

La signature d'un sous-programme

On aura remarqué que le nom des paramètres formels (ceux définis dans la fonction ou la procédure) et ceux des paramètres réels (variables ou constantes utilisés lors de l'appel) sont totalement indépendants. Par contre il faut absolument respecter ce que l'on appelle la signature du sous-programme (procédure ou fonction), à savoir :

  • le nombre de paramètres,
  • le type de chacun des paramètres,
  • l'ordre des paramètres.

Reprenons la fonction conversion() : sa signature constituée par ses paramètres formels est la suivante :

  • nombre de paramètres : deux
  • type du premier paramètre : double
  • type du second paramètre : String
  • ordre des paramètres : double et String

Cela signifie que les appels suivants sont erronés :

AppelsCommentaires
somme = conversion("Dollars", 100);L'ordre des paramètres n'est pas le bon.
somme = conversion(apport);Il manque un paramètre.
somme = conversion(apport, monnaieSrc, monnaieDest);Il y a trop de paramètres.
somme = conversion(apport, 'E');Le type du deuxième paramètre n'est pas le bon (char au lieu de String).

Visibilité et portée des variables

Une variable n'a d'existence que dans le module dans lequel elle a été déclarée (programme principal ou sous-programme).

Ainsi la variable apport déclarée dans le programme principal n'a d'existence que dans celui-ci et n'est pas connue dans la fonction conversion(). De la même manière, la variable resultat de la fonction conversion() n'a aucune existence dans le programme principal.

Le programme principal et chaque sous-programme ont leur espace mémoire où il implante ses données et cet espace n'est partagé avec aucun autre sous-programme ou programme principal.

Le passage par valeur

Que se passerait-il si l'on modifiait la valeur d'un paramètre dans une fonction ? Imaginons le code suivant :

static double conversion(double montant, String devise) {
    double resultat;
    resultat = 0;

    montant /= 2;  // On divise le montant par 2

    if (devise.compareTo("Euros") == 0) {
        resultat = montant * 0.86;
    } else {
        resultat = montant * 1.17;
    }
    return resultat;
}

On divise par deux la valeur de montant. Lorsqu'on lance l'appel suivant :

monnaieSrc = "Euros";
monnaieDest = "Dollars";
somme = conversion(apport, monnaieSrc);
afficher(apport + " " + monnaieSrc + " font : " + somme + " " + monnaieDest);

On obtient l'affichage suivant :

100.0 Euros font : 43.0 Dollars

Lorsqu'on rentre dans la fonction conversion(), on divise par deux la valeur passée en paramètre (100) et on fait donc le calcul sur 50 !

Si on a modifié la valeur du paramètre montant (paramètre formel), est-ce que pour autant cela a modifié la valeur de la variable apport (paramètre réel) ? Non.

En effet, lorsqu'on exécute la ligne suivante : afficher(apport + " " + monnaieSrc + " font : " + somme + " " + monnaieDest); on voit que la variable apport a conservé sa valeur de départ qui était 100 !

À retenir : cela est tout à fait normal, on dit que le passage de paramètres se fait par valeur. Cela signifie que le contenu du paramètre réel (apport) est copié dans le paramètre formel (montant) et que donc la modification de montant n'impacte pas apport.
