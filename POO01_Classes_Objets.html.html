Introduction

Il y a deux types de programmation : la programmation procédurale où l'on découpe un problème en procédures et fonctions afin de le résoudre au mieux, et la programmation orientée objet où l'on aborde une problématique sous l'angle d'objets de gestion (un peu comme dans la méthodologie Merise pour le MCD) que l'on appellera des Classes.

Ces objets de gestion (Facture, Client, Article...) sont envisagés à la fois sous l'angle des données (Propriétés) — par exemple un Client a un nom, une adresse, un chiffre d'affaires — et sous l'angle des traitements (Méthodes) — par exemple pour le Client : créer un nouveau client, ajouter une facture à son chiffre d'affaires, calculer son taux de remise, etc.

Une fois que l'on a déterminé de quelles Classes on a besoin, la construction de notre application consistera essentiellement à faire interagir ces Classes entre elles.

À noter : la POO est un paradigme qui améliore la réutilisation du code, la maintenabilité et la scalabilité des applications. Il permet de modéliser le logiciel de manière à représenter fidèlement les entités du monde réel.
Important : toutes proportions gardées, on se retrouve avec la POO comme on était en abordant pour la première fois l'algorithmique. Nous allons aborder des concepts assez ardus, il ne faut donc pas s'étonner au début de "n'y comprendre rien", c'est tout à fait normal, les choses vont se mettre en place petit à petit. Le couple Cours/TD est très important : le cours expose les concepts et le TD les met en œuvre.

La Classe

Définition

Une classe est un modèle conceptuel (ou blueprint) permettant de représenter un objet du monde réel. Une classe est dotée d'attributs définissant ses caractéristiques et de méthodes définissant son comportement.

En Java, une classe est un type de données défini par l'utilisateur qui regroupe des données et des comportements. Elle peut contenir des champs, des méthodes, des constructeurs, des classes imbriquées et des interfaces.

public class CompteBancaire {
    private String numeroCompte;
    private double solde;

    public void setSolde(double s) {
        this.solde = s;
    }
    public double getSolde() {
        return this.solde;
    }
    public void setNumeroCompte(String n) {
        this.numeroCompte = n;
    }
    public String getNumeroCompte() {
        return this.numeroCompte;
    }
    public void verser(double montant) {
        setSolde(getSolde() + montant);
    }
    public double retirer(double montant) {
        setSolde(getSolde() - montant);
        return getSolde();
    }
}

Une classe est comparable à un moule, par exemple celui d'une casserole. Toutes les casseroles issues de ce moule seront identiques, comme tous les objets créés à partir d'une classe seront identiques. Mais si toutes les casseroles ont la même contenance (propriété) et la même façon de verser le contenu (méthode), elles ne contiendront pas toutes la même chose (soupe, eau, bœuf bourguignon...) et leur contenu ne sera pas versé au même moment par la même personne. Il en va de même avec les classes et les objets.

Exemple concret : Chien est une classe, Tommy est un objet de cette classe. De la même manière, Voiture est une classe, tandis que BMW, Mercedes et Audi sont des objets (instances) créés à partir de cette classe.

Les propriétés

Elles définissent les caractéristiques de la classe. Elles sont typées, en accès privé, et sont accessibles via les accesseurs getXXX() et les mutateurs setXXX() qui doivent être publics.

private String numeroCompte;
private double solde;
Note : le fait de mettre private transforme une simple variable (numeroCompte ou solde) en une propriété. Ce sont ces propriétés qui stockeront les données de la classe.

Accesseurs et mutateurs

Les mutateurs (setters)

Ce sont des procédures admettant un paramètre dont la valeur sera affectée à la propriété. La norme veut que l'on commence toujours un mutateur par set suivi du nom de la propriété (ex. setSolde()). Pour bien marquer que l'on parle de la propriété, on la préfixe de this.

public void setSolde(double s) {
    this.solde = s;
}
public void setNumeroCompte(String n) {
    this.numeroCompte = n;
}
Le préfixe this : il désigne la classe. Quand on écrit this.solde, c'est comme si on disait « je parle de la propriété solde de la classe CompteBancaire ».

Remarque : ici le nom des paramètres est différent du nom des propriétés, mais on voit souvent dans des programmes que le développeur utilise le même nom. On aurait tout aussi bien pu écrire :

public void setSolde(double solde) {
    this.solde = solde;
}

Les accesseurs (getters)

Ce sont des fonctions qui retournent le contenu des propriétés. Par exemple getSolde() va retourner le contenu de la propriété solde. Pour bien marquer que l'on parle de la propriété, on la préfixe également de this.

public double getSolde() {
    return this.solde;
}
public String getNumeroCompte() {
    return this.numeroCompte;
}
Règle : les propriétés privées ne sont accessibles que depuis l'intérieur de la classe et doivent toujours être préfixées de this. Normalement, même à l'intérieur de la classe, on ne devrait accéder aux propriétés que par les accesseurs et mutateurs (sauf bien sûr pour les accesseurs et mutateurs eux-mêmes, qui ne peuvent pas faire autrement).

Note : pour le moment nos propriétés sont constituées par des variables de types simples (String, Double, int...). On verra plus tard qu'une classe peut avoir d'autres classes comme propriétés.

Les méthodes métier

Peuvent être des fonctions (retournent une valeur) ou des procédures, privées (uniquement accessibles depuis l'intérieur de la classe) ou publiques (accessibles depuis l'intérieur et l'extérieur) qui ont pour rôle de « faire » quelque chose.

Par exemple la méthode verser() va ajouter le montant passé en paramètre au solde :

public void verser(double montant) {
    setSolde(getSolde() + montant);
}

Ici on met dans solde le montant actuel de solde (récupéré via getSolde()) auquel on ajoute le montant passé en paramètre.

public double retirer(double montant) {
    setSolde(getSolde() - montant);
    return getSolde();
}

Ici on met dans solde le montant actuel de solde auquel on retire le montant passé en paramètre.

Remarque : on aurait pu écrire this.solde = this.solde + montant; mais cela aurait été moins « propre ». De même, on aurait pu écrire return this.solde; à la place de return getSolde(); — là aussi, moins « propre ».

L'encapsulation

L'encapsulation est le principe permettant de rendre public ce que peut faire une classe (ses méthodes) tout en masquant comment cela est fait.

Avantages de l'encapsulation :
  • Protection des données : les propriétés ne peuvent être modifiées que via les méthodes prévues.
  • Maintenabilité : on peut changer l'implémentation interne sans impacter l'extérieur.
  • Contrôle : on peut valider les valeurs avant de les affecter (ex. vérifier que le solde n'est pas négatif).

L'Objet

Un objet est la réalisation d'une classe. C'est une instance de la classe qui représente une entité du monde réel et permet d'accéder à ses variables et méthodes.

Instancier un objet, c'est créer un objet à partir d'une classe en invoquant son constructeur. Exemple dans une application :

CompteBancaire unCompteBancaire;
unCompteBancaire = new CompteBancaire();

// ou en une seule ligne :
CompteBancaire unCompteBancaire = new CompteBancaire();

unCompteBancaire est un objet de la classe CompteBancaire et la clause new instancie (réalise) l'objet unCompteBancaire.

Parallèle avec les variables classiques :

  • CompteBancaire serait le type et unCompteBancaire la variable.
  • new CompteBancaire() serait l'affectation d'une valeur à la variable.
Attention : il ne s'agit là que d'un parallèle pour se « raccrocher » à quelque chose de connu. En réalité, unCompteBancaire est un objet et CompteBancaire est une Classe.
Les 3 caractéristiques d'un objet :
  • État (State) : les valeurs stockées dans les champs de l'objet.
  • Comportement (Behavior) : les actions définies par les méthodes.
  • Identité (Identity) : chaque objet a une identité unique en mémoire, même si deux objets contiennent les mêmes données.

Le Constructeur

Le constructeur est une méthode minimale d'une classe portant le nom de la classe et permettant d'initialiser les propriétés de la classe. Il est automatiquement invoqué lors de la création d'un objet.

Caractéristiques d'un constructeur :

  • Son nom est identique au nom de la classe.
  • Il n'a aucun type de retour (pas même void).
  • Il est appelé automatiquement lors de l'utilisation du mot-clé new.

Une classe peut disposer de plusieurs constructeurs (surcharge) sous réserve que leurs signatures (nombre, types et ordre des paramètres) soient différentes :

public class CompteBancaire {

    // Constructeur minimal qui initialise à leur valeur par défaut
    // Ici null pour numeroCompte et 0 pour solde
    public CompteBancaire() {
    }

    // Constructeur partiel qui n'initialisera que la propriété numeroCompte
    public CompteBancaire(String numero) {
        this.numeroCompte = numero;
    }

    // Constructeur complet qui initialisera toutes les propriétés
    public CompteBancaire(String numero, double s) {
        setNumeroCompte(numero);
        setSolde(s);
    }
}
Types de constructeurs (GeeksforGeeks) :
  • Constructeur par défaut : ne prend aucun paramètre et initialise l'objet avec des valeurs par défaut.
  • Constructeur paramétré : accepte des paramètres pour initialiser l'objet avec des valeurs spécifiques.
  • Constructeur de copie : crée un nouvel objet en copiant les données d'un autre objet de la même classe.
  • Constructeur privé : empêche la création d'objets depuis l'extérieur de la classe.

Utilisation

On se situe maintenant dans une application qui veut utiliser la classe CompteBancaire. Nous allons envisager plusieurs situations :

a) Aucune valeur disponible → constructeur minimal

CompteBancaire unCompteBancaire = new CompteBancaire();

Les propriétés sont initialisées à leur valeur par défaut : ici numeroCompte sera une chaîne vide et solde vaudra 0.

b) Seulement le numéro → constructeur intermédiaire

CompteBancaire unCompteBancaire = new CompteBancaire("0478523A");

Le numéro du compte aura la valeur "0478523A", et le solde aura la valeur par défaut (0).

c) Toutes les informations → constructeur complet

CompteBancaire unCompteBancaire = new CompteBancaire("0478523A", 100.25);

Le numéro du compte aura la valeur "0478523A", et le solde aura la valeur 100.25.

La Surcharge

La surcharge (overloading) est un dispositif permettant de donner le même nom à plusieurs méthodes, mais en changeant la signature (nombre, types et ordre des paramètres).

public void ajouterSomme(String numero, double valeur) { ... }
public void ajouterSomme(String numero, double valeur, String nom) { ... }
public void ajouterSomme(String nom, double valeur, CompteBancaire unCpt) { ... }

Nous avons vu un premier exemple de surcharge avec les différents constructeurs, et nous aurons l'occasion de revenir sur ce concept.

Notation UML

UML (Unified Modeling Language) est un langage de modélisation des différents composants de la Programmation Orientée Objet. Tout au long de ce cours nous utiliserons une de ses représentations graphiques : le Diagramme de Classes.

Représentation graphique d'une classe dans UML

Nom de la classe
- Liste des propriétés
+ Liste des méthodes

Le signe - indique que l'élément (propriété ou méthode) est privé, et le signe + indique que l'élément est public.

Exemple — Classe Compte

Compte
- numero  : String
- solde    : Double
- decouvert : Double
+ retirer(double montant)          : boolean
+ virer(double montant, Compte compte) : boolean
+ verser(double montant)         : void
Note : cet exemple est loin d'être complet, nous étudierons le Diagramme de Classes de façon plus approfondie plus tard.
