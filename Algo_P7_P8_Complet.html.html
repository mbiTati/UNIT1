Partie 7 — Les collections

Introduction

Jusqu'à maintenant on ne pouvait pas traiter des listes de valeurs, en effet une variable ne peut contenir qu'une seule valeur à la fois. Avec les collections nous allons pouvoir résoudre ce problème.

Remarque : il existe un autre type de structure de données répétitive, ce sont les tableaux. C'était les seules structures répétitives existantes avant que n'apparaissent les collections. Les tableaux ont l'inconvénient d'être statiques en ce sens qu'il faut connaître à l'avance le nombre maximal de valeurs qu'ils peuvent contenir. Si on définissait un nombre trop petit, il fallait modifier les programmes et si on définissait un nombre d'occurrences trop grand, on perdait de la place en mémoire ! À l'inverse les collections sont dynamiques, on peut ajouter autant de valeurs que l'on souhaite sans avoir à modifier le programme. De plus les collections possèdent des fonctionnalités très puissantes que n'ont pas les tableaux. Pour toutes ces raisons les tableaux ne sont pratiquement plus utilisés au profit des collections, donc nous n'étudierons que les collections.

Saisie d'une collection

program Collection {
    List<String> noms;
    String nom;
    
    noms = new ArrayList<String>();
    saisir(nom);
    
    while (nom.compareTo("") != 0) {
        noms.add(nom);
        saisir(nom);
    }
}

Ce programme permet de saisir des noms et de les stocker dans une collection tant que l'on ne saisit pas une chaîne vide.

Analyse

On commence par déclarer une collection. Une collection est forcément typée : c'est une collection de String, ou de Integer, ou de Double. D'autre part l'usage veut (mais ce n'est pas une contrainte technique) que les noms des collections soient toujours au pluriel, pour bien les distinguer des variables simples.

List<String> noms;

Il faut ensuite créer la collection, c'est-à-dire lui donner une existence dans l'espace mémoire du programme. Pour le moment, il faut prendre l'expression ci-dessous telle quelle (nous reviendrons dessus avec la POO).

noms = new ArrayList<String>();

Pour ajouter une valeur dans la collection, on utilise la méthode add().

noms.add(nom);

Les méthodes des collections

Les collections possèdent des méthodes très puissantes qui permettent d'effectuer dessus des traitements. Voici les principales :

MéthodeCommentaires
size()Fournit la taille (nombre de valeurs) de la collection.
get(indice)Récupère la valeur placée à la indiceème position de la collection.
remove(valeur)Supprime cette valeur de la collection.
add(valeur)Ajoute une valeur à la fin de la collection.
set(indice, new_valeur)Remplace la valeur positionnée à la indiceème place par new_valeur.
contains(valeur)Retourne true si la collection contient valeur et false sinon.
indexOf(valeur)Fournit l'indice d'une valeur (sa position) dans la collection si la valeur existe.

Parcourir une collection

Avec un while

program Collection {
    List<String> noms;
    String nom;
    int taille, cpt;
    
    noms = new ArrayList<String>();
    saisir(nom);
    
    while (nom.compareTo("") != 0) {
        noms.add(nom);
        saisir(nom);
    }
    
    taille = noms.size();
    cpt = 0;
    while (cpt < taille) {
        afficher(noms.get(cpt));
        cpt++;
    }
}
Remarque : on aurait tout aussi bien pu écrire while (cpt < noms.size()) { ... } directement.

Pour parcourir une collection on a d'abord besoin de sa taille. En effet si on tente d'accéder à la 20ème valeur d'une collection qui n'en compte que 19, on provoque une erreur fatale qui a pour effet d'arrêter le programme. Pour récupérer une occurrence, on utilise la méthode get(indice).

Avec un for

program CollectionV2 {
    List<String> noms;
    ...
    for (int i=0; i < taille; i++) {
        System.out.println(noms.get(i));
    }
}
Note : lorsque nous étudierons la POO, nous verrons qu'il existe un autre type de boucle for spécifique aux collections (le for-each).

Rechercher et supprimer une occurrence

program CollectionV3 {
    List<String> noms;
    ...
    saisir(nom);
    if (noms.contains(nom)) {
        noms.remove(nom);
    }
}

La suppression d'une occurrence a pour effet de réduire la taille de la collection de 1 et de décaler vers le haut le reste des occurrences. Illustration :

PositionValeur
0Pierre
1Marie
2Jacques
3Anne
4Paul

Taille : 5

Collection après suppression de "Jacques" :

PositionValeur
0Pierre
1Marie
2Anne
3Paul

Taille : 4

Attention : la suppression d'une occurrence à l'intérieur d'une boucle parcourant cette même collection peut provoquer une erreur d'exécution si l'on passe par une variable. Dans ce cas il est préférable d'utiliser directement la méthode size().

Exercices — Partie 7

Ex1 : Saisir une liste de prénoms et afficher cette liste du dernier au premier.

Ex2 : Saisir une liste de villes et copier chacune de ces villes dans une autre collection en commençant par la dernière, puis afficher la liste des villes de la deuxième collection.

Ex3 : Afficher la position d'un nom (nom saisi par l'utilisateur) dans une liste de noms. Attention : pour trouver la position d'un nom il faut d'abord s'assurer que celui-ci fasse partie de la collection !

Ex4 : Dans une liste de couleurs, remplacer la première par la dernière, puis la deuxième par l'avant-dernière et ainsi de suite, à la fin afficher la liste inversée.

Aide : on va avoir besoin d'une variable intermédiaire. Voyons ce qui se passe avec une simple liste de lettres : A B C D E. Remplacement de A par E : E B C D E — on a perdu le A ! La méthode consiste à mettre A dans une variable intermédiaire, remplacer A par E, puis remplacer E par le contenu de la variable intermédiaire.

Ex5 : Même exercice que l'exercice 2, mais chaque fois que l'on copie une ville dans l'autre liste, on la supprime de la première.

Aide : cet exercice est particulièrement délicat. On peut résoudre le problème en copiant systématiquement la première ville de la collection, puis on supprime cette ville.

Partie 8 — Les sous-programmes (Fonctions et Procédures)

Le problème du code répété

Lorsque les programmes deviennent complexes et comportent de nombreuses lignes de code, il devient nécessaire de les découper en sous-programmes (procédures ou fonctions) soit pour partager du code en plusieurs endroits, soit pour les rendre plus lisibles et donc plus facilement maintenables.

Supposons un programme demandant à un utilisateur de saisir les coordonnées de quatre points d'un rectangle, sachant que l'ordonnée doit être comprise entre 0 et 480 et l'abscisse entre 0 et 640. L'algorithme pourrait ressembler à ceci :

program Points {
    saisir(ordonnee);
    saisir(abscisse);
    if ((ordonnee >= 0) && (abscisse <= 480) && (abscisse >= 0) && (abscisse <= 640)) {
        point1 = true;
    } else {
        point1 = false;
    }
    saisir(ordonnee);
    saisir(abscisse);
    if ((ordonnee >= 0) && (abscisse <= 480) && (abscisse >= 0) && (abscisse <= 640)) {
        point2 = true;
    } else {
        point2 = false;
    }
    // ... répété 4 fois
}
Important : on voit bien que le test de validité des coordonnées est répété plusieurs fois. Pour éviter cela on va mettre en facteur commun les instructions réalisant ce test, il suffira d'appeler ces lignes pour en récupérer le résultat.

Les fonctions

Voici comment extraire le test dans une fonction verifie() :

program PointsV2 {
    saisir(ordonnee);
    saisir(abscisse);
    point1 = verifie();

    saisir(ordonnee);
    saisir(abscisse);
    point2 = verifie();
    // ...
}

static boolean verifie() {
    boolean point;
    if ((ordonnee >= 0) && (abscisse <= 480) && (abscisse >= 0) && (abscisse <= 640)) {
        point = true;
    } else {
        point = false;
    }
    return point;
}
Note : pour le moment nous ignorerons le mot static qui figure au début de la déclaration de la fonction verifie().

Analyse du pointeur de programme

ÉtapeInstructionCommentaire
1saisir (ordonnee); saisir (abscisse);Saisie des valeurs dans les variables ordonnee et abscisse.
2point1 = verifie();La variable point1 doit être affectée par une valeur fournie par l'élément à droite. Cet élément n'étant ni une constante, ni une variable, il s'agit donc d'une fonction. Le pointeur de programme va se déplacer jusqu'à la première instruction de cette fonction.
3if (...) { point = true; } else { point = false; }Nous sommes dans la fonction verifie() et on procède à l'évaluation des conditions. On utilise la variable locale point pour gérer la valeur retournée.
4return point;Sortie de la fonction en mettant le contenu de la variable point dans une zone tampon du programme.
5point1 < verifie()Affectation du contenu de la zone tampon à la variable point1.
6saisir (ordonnee); saisir (abscisse);Suite du programme sur le même principe.

Indicateurs d'une fonction :

  1. Elle est typée (ici boolean) : boolean verifie() {
  2. Elle retourne une valeur du même type que celui déclaré : return point;

Comme c'est une fonction, on peut donc utiliser la valeur retournée pour affecter une variable : point1 = verifie();.

Les procédures

Imaginons que nous voulions mettre en facteur commun la saisie de l'ordonnée et de l'abscisse. On ne peut pas utiliser une fonction, car une fonction ne retourne qu'une seule valeur alors qu'on a besoin de deux valeurs. On va donc utiliser une procédure :

program PointsV2 {
    saisie();
    point1 = verifie();

    saisie();
    point2 = verifie();
    // ...
}

static void saisie() {
    saisir(ordonnee);
    saisir(abscisse);
}

static boolean verifie() {
    // ... (inchangé)
}

Indicateurs d'une procédure :

  1. Son type est void (vide), donc il n'est pas typé : static void saisie() {
  2. Il n'y a pas de return dedans.

On peut constater que notre programme a gagné en lisibilité et en taille ! Au lieu d'écrire 4 fois les deux instructions de saisie, on écrit seulement 4 fois l'appel à la procédure saisie();.
